# Конструктор коммерческих предложений

Собирает КП в PDF: HTML-шаблон + Jinja2 → рендер через Chromium (Playwright). Печать и подпись накладываются как прозрачные PNG с `mix-blend-mode: multiply` — выглядят как оттиск на бумаге, а не как наклейка поверх текста.

## Что нужно один раз

Перед первым запуском проверь, что заполнены `assets/brand.json` и лежат файлы в `assets/`:

| Файл | Требование |
|---|---|
| `logo.png` | прозрачный фон, высота от 200 px |
| `stamp.png` | прозрачный фон, квадрат от 600×600 px, синий оттиск без белой подложки |
| `signature.png` | прозрачный фон, чёрная или синяя линия |

Проверка одной командой:

```bash
python scripts/check_assets.py
```

Скрипт скажет, у какого файла осталась белая подложка вместо прозрачности — это главная причина, почему печать выглядит наклеенной. Как чистить фон и готовить сканы — `references/stamping.md`.

## Как собрать КП

1. **Собери данные в JSON.** Структура — `assets/kp.example.json`. Обязательны: `client`, `items` (позиции с `name`, `qty`, `unit`, `price`), `valid_until`. Если данные пришли из парсинга или поиска, приведи их к этой структуре сам, не спрашивай пользователя про каждое поле.

2. **Проверь цифры до рендера.** Скрипт считает суммы сам, но исходные цены не проверяет. Если цена выглядит как ошибка на порядок — спроси, не молчи.

3. **Собери PDF:**

```bash
python scripts/build_kp.py --data kp.json --out "КП_Клиент_2026-09-12.pdf"
```

Флаги:
- `--no-stamp` — черновик без печати и подписи (для внутреннего согласования)
- `--html-only` — только HTML, посмотреть вёрстку без рендера
- `--brand path.json` — другой набор реквизитов, если компаний несколько

4. **Покажи результат.** Если есть `present_files` — отдай PDF через него. Иначе назови путь к файлу.

## Правила, которые нельзя нарушать

**Печать и подпись ставятся только на финальную версию.** Если пользователь просит черновик, версию «на посмотреть», вариант для обсуждения — собирай с `--no-stamp`. Подписанный документ, ушедший клиенту по ошибке, отзывать поздно.

**Не выдумывай реквизиты.** Всё, чего нет в `brand.json` и входном JSON — не подставляй. Пустое поле лучше правдоподобного вымысла в документе с подписью.

**Не генерируй печать и подпись.** Только реальные файлы из `assets/`. Если `stamp.png` отсутствует — скажи об этом и собери без печати, но не рисуй замену.

**Срок действия обязателен.** Нет `valid_until` — поставь 14 дней от даты сборки и скажи пользователю, что подставил дефолт.

## Структура документа

Шапка с логотипом и реквизитами → блок клиента и номера КП → вводный абзац → таблица позиций → итоги с НДС → условия и сроки → подпись с расшифровкой → печать поверх подписи со смещением → футер с контактами.

Таблица разрывается по страницам корректно: шапка повторяется, блок итогов не отрывается от последней строки. Печать и подпись всегда на последней странице — за это отвечает CSS в `assets/template.html`, не трогай позиционирование без причины.

## Правка вёрстки

Цвета, шрифты и геометрия печати — только в `assets/brand.json`. HTML-шаблон трогай, если меняется состав блоков, а не их вид.

Смещение печати относительно подписи задаётся в `brand.json` → `stamp`: `size_mm`, `rotate_deg`, `offset_x_mm`, `offset_y_mm`, `opacity`. Оттиск должен частично перекрывать подпись — так подписывают на бумаге. Полностью в стороне выглядит фальшиво, полностью поверх — прячет подпись.

## Если Playwright не установлен

```bash
pip install playwright jinja2 && playwright install chromium
```

Запасной путь без браузера — WeasyPrint (`pip install weasyprint`), скрипт переключится сам, но `mix-blend-mode` там не поддерживается: печать ляжет плоской. Для отправки клиенту используй Chromium.
