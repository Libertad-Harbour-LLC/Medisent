## 1. Что делает бот

Вы пишете боту в Telegram, что нужно купить. Дальше он делает всё сам и
возвращается к вам дважды: показать отчёт и показать цифры перед сборкой
документа.

```
Вы: фото коробки / голосовое / текст / файл
              │
              ▼
   [1] Распознаёт, что за изделие              ← Gemini
              │
              ▼
   [2] Ищет поставщиков                        ← Perplexity
   [3] Читает их сайты: наличие, цена, контакты ← Firecrawl
   [4] Проверяет изделие в реестрах            ← Росздравнадзор
              │
              ▼
   [5] Присылает вам отчёт ────────────────────► ВЫ ЧИТАЕТЕ
              │
   Вы отвечаете голосовым: «беру второго, привезёт быстрее»
              │
              ▼
   [6] Запоминает, почему вы так решили
       (в следующий раз учтёт сам)
              │
              ▼
   [7] Пишет письмо выбранному поставщику      ← Gmail
       Ждёт ответ, ловит его, присылает вам
              │
              ▼
   [8] Достаёт цены из письма ─────────────────► ВЫ ПРОВЕРЯЕТЕ ЦИФРЫ
              │
              ▼
   Собирает коммерческое предложение в PDF
```

**Два места, где бот обязательно спрашивает вас**, и обойти их нельзя:

- **После отчёта.** Кого выбрать — решаете вы. Бот только раскладывает данные.
- **Перед сборкой КП.** Цены в письмах приходят с оговорками: «без НДС»,
  «от 10 штук», «при 100% предоплате». Неверно понятая цена уйдёт клиенту под
  вашей печатью, поэтому бот сначала показывает числа вам.

### Два поля, которые никогда не смешиваются

В отчёте по каждому поставщику вы увидите две отдельные строки:

```
1. ООО «Медтехника»
   medtech.ru
   РУ на изделие: РУ ФСР 2010/08183 · АО «Эй энд Ди РУС» · действует · реестр misearch
   Поставщик: заявляет наличие
```

- **«РУ на изделие»** — из государственного реестра. Это про **изделие**:
  зарегистрировано ли оно в России, кто держатель удостоверения, действует ли
  оно. Про поставщика реестр не знает ничего: дилеров в нём нет вообще.
- **«Поставщик»** — то, что компания написала **у себя на сайте**. Это её
  собственное заявление, никем не проверенное.

Строки «поставщик проверен в Росздравнадзоре» вы не увидите никогда — такого
факта не существует, и бот его не выдумывает.

Третий возможный вариант первой строки: **«проверить не удалось, реестр
недоступен»**. Это не то же самое, что «не найдено». «Не нашли» значит, что
изделия в реестре нет. «Не смогли проверить» значит, что сайт реестра не
ответил, и знать мы ничего не знаем.

## 2. Какой сервис за что отвечает

| Сервис | Что делает | Без него |
|---|---|---|
| **Telegram** | Вы общаетесь с ботом | Бот не запустится |
| **Railway** | Место, где бот живёт круглосуточно | Бот не запустится |
| **PostgreSQL** (внутри Railway) | Хранит заявки, поставщиков, критерии | Бот не запустится |
| **Gemini** | Распознаёт фото, голос и файлы; пишет отчёт и письма | Работает только текстовый ввод |
| **Perplexity** | Ищет поставщиков в интернете | Поиска нет, всё остальное работает |
| **Firecrawl** | Читает сайты поставщиков | Наличия и цен с сайтов не будет |
| **Gmail** | Отправляет письма и ловит ответы | Писем и КП не будет |
| **Mathesar** | Показывает таблицы бота в браузере | Смотреть данные будет негде |
| **Росздравнадзор** | Проверка регистрации изделия | Ключей не нужно, но сайт может быть недоступен |

**Первые три обязательны.** Остальное можно подключать по мере надобности:
бот запускается и честно пишет в чат, что именно у него выключено.

## 3. Сколько это стоит

| Сервис | Тариф | Ориентир в месяц |
|---|---|---|
| Telegram | бесплатно | 0 ₽ |
| Railway | от $5 за использованные ресурсы | $5–15 |
| Gemini | есть бесплатный лимит, дальше по токенам | $0–5 |
| Perplexity | ~$0.006 за поиск | $2–10 |
| Firecrawl | есть бесплатный лимит, дальше ~$0.001 за страницу | $0–10 |
| Gmail | бесплатно в пределах обычных квот | 0 ₽ |

Итого при десятке заявок в месяц — примерно **$10–25**.

Бот считает расходы сам. Команда `/stats` показывает траты за сегодня по
каждому сервису. Переменная `DAILY_API_BUDGET_USD` задаёт мягкий потолок: при
его превышении бот **предупреждает и продолжает работу**, не блокируется.

## 4. Что приготовить заранее

- [ ] Компьютер с браузером. Ничего устанавливать не нужно.
- [ ] Аккаунт GitHub (бесплатный) — там уже лежит код.
- [ ] Банковская карта — Railway и Perplexity потребуют привязать.
- [ ] Отдельный ящик Gmail, с которого будут уходить письма поставщикам.
      **Заведите новый, не используйте личный** — бот будет читать почту этого
      ящика.
- [ ] Реквизиты вашей компании и три картинки для КП (см. шаг 10).
- [ ] Три реальных изделия для проверки: одно зарегистрировано до 01.03.2025,
      одно после, одно выдуманное.

Заведите текстовый файл и складывайте туда ключи по ходу. В конце перенесёте
их одним махом.

## Шаг 1. Telegram: создать бота

**Что получим:** `TELEGRAM_BOT_TOKEN` и `TELEGRAM_OWNER_ID`.

### 1.1. Создать бота

1. Откройте Telegram, в поиске введите **@BotFather** и откройте чат с ним
   (у него синяя галочка).
2. Нажмите **Start** или отправьте `/start`.
3. Отправьте `/newbot`.
4. BotFather спросит имя — это то, что видно в заголовке чата. Напишите,
   например: `Medisent`
5. Спросит username — он должен быть уникальным и заканчиваться на `bot`.
   Например: `medisent_supply_bot`

**Что должно появиться:**

```
Done! Congratulations on your new bot. You will find it at
t.me/medisent_supply_bot

Use this token to access the HTTP API:
8012345678:AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw

Keep your token secure and store it safely.
```

Длинная строка с двоеточием — это `TELEGRAM_BOT_TOKEN`. Скопируйте её.

> **Не показывайте токен никому и не выкладывайте в переписку.** Кто им
> владеет — управляет ботом. Если случайно засветили: `/token` у BotFather
> выдаст новый, старый перестанет работать.

### 1.2. Узнать свой числовой id

1. В поиске Telegram найдите **@userinfobot**, откройте чат.
2. Отправьте `/start`.

**Что должно появиться:**

```
Id: 384729103
First: Иван
Username: @ivan
```

Число после `Id:` — это `TELEGRAM_OWNER_ID`. Бот будет отвечать только на
сообщения с этого id, всем остальным — «Бот работает только с владельцем».

## Шаг 3. Railway: база данных

**Что получим:** `DATABASE_URL`.

Railway — это место, где программа работает круглосуточно, вместо вашего
компьютера. Своим сервером управлять не придётся.

### 3.1. Регистрация

1. Откройте **https://railway.com**
2. Нажмите **Login** → **Login with GitHub**.
3. Разрешите доступ.
4. Railway попросит привязать карту (Settings → Billing). Без неё проект
   уснёт через несколько часов.

### 3.2. Создать проект и базу

1. На главной нажмите **New Project**.
2. Выберите **Deploy PostgreSQL**.

**Что должно появиться:** прямоугольник с надписью **Postgres** и зелёной
точкой. Точка означает, что база запущена.

3. Кликните на прямоугольник **Postgres** → вкладка **Variables**.
4. Найдите строку **`DATABASE_URL`**, нажмите на значок копирования.

Значение выглядит так:

```
postgresql://postgres:kQzR7xLmNp2WvBd@centerbeam.proxy.rlwy.net:41234/railway
```

Сохраните её в свой файл с ключами.

> **Одна правка обязательна.** Бот работает с базой асинхронно и требует
> другого написания начала строки. Замените
> `postgresql://` на `postgresql+asyncpg://`, всё остальное оставьте:
>
> ```
> postgresql+asyncpg://postgres:kQzR7xLmNp2WvBd@centerbeam.proxy.rlwy.net:41234/railway
> ```
>
> Если забудете — бот при запуске напишет об этом прямым текстом и не
> стартует. Испортить ничего не успеет.

### 3.3. Проверка

Кликните **Postgres** → вкладка **Data**. Должна открыться пустая таблица —
базы ещё нет, но соединение работает.

## Шаг 4. Railway: сам бот

**Что получим:** работающий бот.

### 4.1. Добавить сервис

1. В том же проекте нажмите **+ New** (справа сверху) → **GitHub Repo**.
2. Если Railway не видит репозиторий: **Configure GitHub App** → отметьте
   `Libertad-Harbour-LLC/Medisent` → **Save**.
3. Выберите репозиторий из списка.

**Что должно появиться:** второй прямоугольник рядом с Postgres. Railway
сразу попытается собрать бота и, скорее всего, покажет красный крестик —
это нормально, переменных ещё нет.

### 4.2. Выбрать правильную ветку

1. Кликните на прямоугольник бота → **Settings**.
2. Раздел **Source** → **Branch** → выберите `claude/bot-specification-4anoex`.

### 4.3. Вписать переменные

1. Вкладка **Variables** → кнопка **Raw Editor**.
2. Вставьте текст ниже, подставив свои значения вместо `ВАШ_...`:

```
TELEGRAM_BOT_TOKEN=ВАШ_ТОКЕН_ОТ_BOTFATHER
TELEGRAM_OWNER_ID=ВАШ_ЧИСЛОВОЙ_ID
DATABASE_URL=postgresql+asyncpg://ВАША_СТРОКА_ИЗ_ШАГА_3
LOG_LEVEL=INFO
DAILY_API_BUDGET_USD=5.0
```

3. Нажмите **Update Variables**. Railway пересоберёт бота автоматически.

Остальные ключи добавим на следующих шагах — бот запускается и без них.

### 4.4. Применить миграции (создать таблицы)

Таблицы в базе создаются одной командой.

1. Кликните на прямоугольник бота → вкладка **Settings** → раздел **Deploy**.
2. В поле **Custom Start Command** временно впишите:

```
alembic upgrade head && python -m bot.main
```

3. **Save**. Railway перезапустит бота.

**Что должно появиться в логах** (вкладка **Deployments** → верхняя запись →
**View Logs**):

```
INFO  [alembic.runtime.migration] Running upgrade  -> 0001, Начальная схема
2026-09-12 19:20:14 INFO  [-] __main__: Запуск бота. Предупреждений: 4
2026-09-12 19:20:15 INFO  [-] __main__: Бот @medisent_supply_bot готов
```

Строка **«Бот … готов»** означает успех. Команду из шага 4.4 можно оставить
как есть: повторный `alembic upgrade head` ничего не портит, а при будущих
обновлениях сам применит новые миграции.

### 4.5. Проверка

Откройте своего бота в Telegram и отправьте `/start`.

**Что должно появиться:**

```
Бот подбора поставщиков медизделий.

Пришлите запрос: текстом, фото коробки, голосовым или файлом.
Я найду поставщиков, проверю изделие в реестрах Росздравнадзора
и пришлю отчёт.
```

Если пришло — этап 0 и этап 1 приняты. Всё остальное можно подключать
постепенно.

Попросите знакомого написать вашему боту. Он должен получить
**«Бот работает только с владельцем»** — значит, whitelist работает.

## Шаг 5. Gemini: распознавание фото и голоса

**Что получим:** `GEMINI_API_KEY`.

Gemini делает четыре вещи: читает фото коробки, расшифровывает ваши
голосовые, вытаскивает описание изделия из PDF и составляет тексты отчёта и
письма.

1. Откройте **https://aistudio.google.com/apikey**
2. Войдите под своим Google-аккаунтом.
3. Нажмите **Create API key**.
4. Если попросит выбрать проект — **Create API key in new project**.

**Что должно появиться:** строка вида `AIzaSyD-1a2B3c4D5e6F7g8H9i0J...`
Скопируйте её.

5. В Railway → сервис бота → **Variables** → **Raw Editor** добавьте:

```
GEMINI_API_KEY=ваш_ключ
LLM_REPORT_MODEL=gemini-flash-latest
LLM_EMAIL_MODEL=gemini-flash-latest
```

**Проверка:** отправьте боту фото любой коробки от медицинского изделия.
Он ответит «Смотрю фото…», потом назовёт изделие.

> Бесплатного лимита Gemini хватает на десятки заявок в месяц. Оплата
> подключается там же, в AI Studio, если лимит начнёт кончаться.

## Шаг 6. Perplexity: поиск поставщиков

**Что получим:** `PERPLEXITY_API_KEY`.

1. Откройте **https://www.perplexity.ai/settings/api**
2. Зарегистрируйтесь или войдите.
3. В разделе **API Keys** сначала придётся пополнить баланс:
   **Buy Credits**, минимально $5 — этого хватит надолго, один поиск стоит
   меньше цента.
4. Нажмите **Generate** (или **Create API Key**).

**Что должно появиться:** строка вида `pplx-1a2b3c4d5e6f7g8h9i0j...`

> Ключ показывается **один раз**. Скопируйте сразу; потерян — генерируйте
> новый, старый удаляйте.

5. В Railway добавьте:

```
PERPLEXITY_API_KEY=pplx-ваш_ключ
```

**Проверка:** напишите боту `тонометр автоматический на плечо`. Он ответит
«Ищу поставщиков…», через минуту-две — «Нашёл кандидатов: N».

## Шаг 7. Firecrawl: чтение сайтов

**Что получим:** `FIRECRAWL_API_KEY`.

Firecrawl открывает сайты поставщиков и достаёт оттуда наличие, цену, почту и
телефон. Обычный запрос к сайту вернул бы кашу из меню и баннеров.

1. Откройте **https://www.firecrawl.dev**
2. **Sign Up** → войдите через Google или GitHub.
3. После входа вы попадёте на Dashboard. Слева выберите **API Keys**.
4. Скопируйте ключ или нажмите **Create API Key**.

**Что должно появиться:** строка вида `fc-1a2b3c4d5e6f...`

5. В Railway добавьте:

```
FIRECRAWL_API_KEY=fc-ваш_ключ
SCRAPE_CONCURRENCY=5
```

**Проверка:** повторите запрос из шага 6. Теперь в отчёте у поставщиков
появятся строки «заявляет наличие» и цены.

> Бесплатного тарифа (500 страниц) хватает примерно на 50 заявок.

## Шаг 8. Gmail: письма поставщикам

**Что получим:** `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`,
`GOOGLE_REFRESH_TOKEN`, `GMAIL_SENDER`, `FORWARD_TO_EMAIL`.

**Это самый долгий шаг — минут 40.** Google требует явно разрешить программе
доступ к почте, и разрешение оформляется в несколько экранов. Ниже — по
шагам.

> **Заведите отдельный ящик Gmail для бота.** Он будет читать всю входящую
> почту этого ящика, чтобы находить ответы поставщиков. Личный ящик для этого
> использовать не нужно.

### 8.1. Создать проект в Google Cloud

1. Откройте **https://console.cloud.google.com**
2. Войдите под ящиком бота.
3. Сверху, рядом с логотипом Google Cloud, нажмите на выпадающий список
   проектов → **New Project**.
4. Имя: `Medisent` → **Create**.
5. Дождитесь уведомления и переключитесь на новый проект в том же списке.

**Что должно появиться:** вверху рядом с логотипом написано `Medisent`.

### 8.2. Включить Gmail API

1. В строке поиска сверху введите `Gmail API` и выберите его.
2. Нажмите синюю кнопку **Enable**.

**Что должно появиться:** страница «Gmail API» с надписью **API enabled** и
серой кнопкой **Manage** вместо синей **Enable**.

### 8.3. Настроить экран согласия

1. Слева: **APIs & Services** → **OAuth consent screen**.
2. Выберите **External** → **Create**.
3. Заполните три обязательных поля:
   - **App name**: `Medisent`
   - **User support email**: ящик бота
   - **Developer contact information**: тот же ящик
4. **Save and Continue**.
5. Экран **Scopes** — просто **Save and Continue**, ничего не добавляйте.
6. Экран **Test users** → **+ Add Users** → впишите ящик бота → **Add** →
   **Save and Continue**.
7. **Back to Dashboard**.

### 8.4. Опубликовать приложение — не пропускайте

На той же странице **OAuth consent screen** найдите раздел
**Publishing status**. Там написано **Testing**.

Нажмите **PUBLISH APP** → в окне подтверждения **Confirm**.

**Что должно появиться:** Publishing status: **In production**.

> **Зачем это нужно.** Пока статус «Testing», ключ доступа, который мы
> получим ниже, **протухает через 7 дней**. Бот перестанет читать почту
> ровно через неделю, причём молча — в логах будет «не удалось обновить
> токен Google». Публикация снимает ограничение.
>
> Проверку Google запрашивать не нужно: приложением пользуетесь только вы.
> При входе будет показан экран «Google hasn't verified this app» — это
> ожидаемо, там надо нажать **Advanced** → **Go to Medisent (unsafe)**.

### 8.5. Создать ключ доступа

1. Слева: **APIs & Services** → **Credentials**.
2. Сверху **+ Create Credentials** → **OAuth client ID**.
3. **Application type**: **Web application**.
4. **Name**: `Medisent bot`.
5. Раздел **Authorized redirect URIs** → **+ Add URI**. Вставьте **ровно
   этот адрес**, без пробелов и без косой черты в конце:

```
https://developers.google.com/oauthplayground
```

6. **Create**.

**Что должно появиться:** окно **OAuth client created** с двумя строками —
**Client ID** (заканчивается на `.apps.googleusercontent.com`) и
**Client secret** (начинается на `GOCSPX-`). Скопируйте обе.

### 8.6. Получить refresh-токен

1. Откройте **https://developers.google.com/oauthplayground**
2. Справа сверху нажмите **шестерёнку** (⚙).
3. Поставьте галочку **Use your own OAuth credentials**.
4. В появившиеся поля вставьте **Client ID** и **Client secret** из 8.5.
5. Закройте панель настроек (щёлкните по шестерёнке ещё раз).
6. Слева, в списке **Step 1**, промотайте в самый низ до поля
   **Input your own scopes**. Вставьте туда обе строки через пробел:

```
https://www.googleapis.com/auth/gmail.send https://www.googleapis.com/auth/gmail.readonly
```

7. Нажмите синюю **Authorize APIs**.
8. Выберите ящик бота.
9. Экран **«Google hasn't verified this app»** → **Advanced** →
   **Go to Medisent (unsafe)**.
10. На экране разрешений нажмите **Continue** (Google попросит два доступа:
    отправку писем и чтение).
11. Вернётесь в Playground, откроется **Step 2**. Нажмите
    **Exchange authorization code for tokens**.

**Что должно появиться:** справа в чёрном поле — JSON. В нём строка:

```json
{
  "access_token": "ya29.a0AfB_...",
  "expires_in": 3599,
  "refresh_token": "1//0gLm3xQ7kR9pT...",
  "scope": "https://www.googleapis.com/auth/gmail.readonly https://www.googleapis.com/auth/gmail.send",
  "token_type": "Bearer"
}
```

Нужна строка **`refresh_token`** — значение начинается на `1//`. Скопируйте
его **без кавычек**.

> **Если `refresh_token` в ответе нет** — значит, вы уже давали это
> разрешение раньше. Откройте
> **https://myaccount.google.com/permissions**, найдите `Medisent`, нажмите
> **Remove access** и повторите шаг 8.6 с начала.

**Альтернатива для тех, у кого есть Python на компьютере.** В репозитории
лежит скрипт, который делает то же самое сам:

```bash
python3 scripts/get_gmail_token.py
```

Он спросит Client ID и secret, откроет браузер и выведет готовые строки.
В этом случае в шаге 8.5 в Authorized redirect URIs надо добавить
`http://localhost:8765/` вместо адреса Playground.

### 8.7. Вписать в Railway

```
GOOGLE_CLIENT_ID=1234567890-abc.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-ваш_секрет
GOOGLE_REFRESH_TOKEN=1//0gLm3xQ7kR9pT...
GMAIL_SENDER=ящик-бота@gmail.com
FORWARD_TO_EMAIL=куда-пересылать-файлы@example.com
GMAIL_POLL_SECONDS=240
```

`GMAIL_SENDER` — тот самый ящик бота. `FORWARD_TO_EMAIL` — куда бот перешлёт
файл по команде `/forward`; это может быть ваш обычный рабочий адрес.

**Проверка:** в логах Railway после перезапуска не должно быть строки
«Gmail не настроен». Отправьте боту любой PDF с подписью `/forward` —
файл должен прийти на указанный адрес.

## Шаг 9. Mathesar: таблицы в браузере

**Что получим:** возможность смотреть и править данные бота глазами.

## Первый запуск

Полный прогон, чтобы убедиться, что всё связано.

### Проверка 1. Бот отвечает

Отправьте `/start`.

**Ожидается:** приветствие. **Если тишина** — см. «Бот не отвечает» ниже.

### Проверка 2. Чужих не пускает

Попросите знакомого написать боту.

**Ожидается:** «Бот работает только с владельцем».

### Проверка 3. Расходы считаются

Отправьте `/stats`.

**Ожидается:** «Сегодня внешние сервисы не вызывались» либо список трат.

### Проверка 4. Полный цикл

Отправьте фото коробки реального изделия.

**Ожидается по шагам:**

```
Смотрю фото…
Изделие: Тонометр автоматический UA-777
Количество: не указано
Заявка: RFQ-2026-001

Ищу поставщиков…
Нашёл кандидатов: 7
Собираю отчёт…

Отчёт по заявке RFQ-2026-001
Изделие: Тонометр автоматический UA-777

1. ООО «Медтехника»
   medtech.ru
   РУ на изделие: РУ ФСР 2010/08183 · АО «Эй энд Ди РУС» · действует · реестр misearch
   Поставщик: заявляет наличие
   Цена на сайте: 12 500 ₽
   Контакты: sales@medtech.ru · +7 495 000-00-00
   …

Ответьте голосовым: кого берём и почему.
```

Весь цикл занимает 1–3 минуты. Долго — это нормально: бот ходит в четыре
разных сервиса и обходит до десяти сайтов.

### Что бот делает не так, как можно ожидать

Три места, где поведение специально «неудобное», чтобы не было хуже:

- **Кнопка «Да» под письмом действует сутки.** Нажмёте позже — бот скажет, что
  подтверждение недействительно, и попросит выбрать заново. Так сделано, чтобы
  случайное нажатие на старую кнопку не отправило письмо поставщику.
- **Повторный выбор того же поставщика второго письма не отправит.** Бот
  ответит, что письмо уже отправлялось.
- **Если выбора ждут сразу две заявки, бот спросит, о какой речь.** Угадывать
  он не будет: критерии уехали бы к чужим поставщикам, и вернуть их было бы
  нечем. Закройте лишнюю через `/cancel` или назовите номер заявки голосом.

### Проверка 5. Голосовой выбор

Ответьте голосовым: «беру второго, он привезёт быстрее, а разница в цене
небольшая».

**Ожидается:**

```
Запомнил критериев: 1. Учту в следующих отчётах.
Выбран ООО «Медтехника». Готовлю письмо.

Письмо поставщику ООО «Медтехника» на sales@medtech.ru:
[текст письма]

Отправляем?   [Да] [Нет]
```

### Проверка 6. Данные легли в базу

Откройте Mathesar. В таблице `requests` — строка с вашим токеном, в
`suppliers` — найденные компании, в `criteria` — критерий из голосового.

2. **Зарегистрированное после 01.03.2025** — должно быть `реестр elk`.

## Когда что-то пошло не так

### Бот не отвечает на `/start`

**Шаг 1.** Railway → сервис бота → **Deployments** → верхняя запись →
**View Logs**. Ищите последние строки.

| Что в логах | Что это значит | Что делать |
|---|---|---|
| `Бот @… готов` | Бот работает, дело в другом | Проверьте, что пишете именно своему боту (username из шага 1.1) |
| `Unauthorized` | Токен неверный | Перепроверьте `TELEGRAM_BOT_TOKEN`, лишний пробел в начале или конце тоже ломает |
| `DATABASE_URL должен начинаться с` | Забыли `+asyncpg` | Исправьте переменную по шагу 3.2 |
| `password authentication failed` | Неверный пароль базы | Скопируйте `DATABASE_URL` из Postgres заново |
| `relation "requests" does not exist` | Таблицы не созданы | Выполните шаг 4.4 |
| Логи пустые, статус **Crashed** | Сборка не прошла | Смотрите вкладку **Build Logs** |

**Шаг 2.** Отвечает не вам? Проверьте `TELEGRAM_OWNER_ID` — это должно быть
число без пробелов, кавычек и знака `@`.

### Бот отвечает, но пишет «Поиск выключен»

Не задан `PERPLEXITY_API_KEY`. Так и должно быть, если вы ещё не делали шаг 6.

### Все поставщики без цен и без «в наличии»

Не задан `FIRECRAWL_API_KEY` (шаг 7) либо закончился лимит. Проверьте баланс
на dashboard Firecrawl.

### По всем изделиям «проверить не удалось, реестр недоступен»

Это самая вероятная проблема этапа 2, и решается она не в Railway.

**Причина 1: сайт реестра лежит.** Откройте
https://roszdravnadzor.gov.ru/services/misearch в браузере. Не открывается у
вас — не откроется и у бота. Подождите.

**Причина 2: изменился формат ответа.** Реестры — государственные сайты, их
верстку и API меняют без предупреждения. Бот это замечает и честно пишет
«не смог», а не выдаёт пустой результат за «не найдено».

Что делать: поправить один файл —
[`bot/services/registry_endpoints.py`](../bot/services/registry_endpoints.py).
Как именно, расписано в шапке самого файла: открыть виджет реестра в
браузере, снять реальные запросы через F12 → Network и подставить их.
Это работа программиста, но она локализована в одном файле, остальной код
трогать не надо.

**Чего делать нельзя:** заменять проверку реестра ответом языковой модели.
Модель назовёт правдоподобный номер РУ, которого не существует, и он уйдёт в
документ.

### Бот перестал ловить ответы поставщиков ровно через неделю

Вы пропустили **шаг 8.4** — публикацию приложения в Google Cloud. В статусе
«Testing» refresh-токен живёт 7 дней.

Что делать: выполните шаг 8.4, затем заново получите токен по шагу 8.6 и
обновите `GOOGLE_REFRESH_TOKEN` в Railway.

### «не удалось обновить токен Google» в логах

Refresh-токен отозван или протух. Причины: публикация не сделана (см. выше),
пароль от ящика меняли, доступ отозвали вручную на
https://myaccount.google.com/permissions.

Что делать: пройдите шаг 8.6 заново.

### КП собралось с чужой компанией в шапке

Не выполнен шаг 10.1. Замените `brand.json`.

### КП собралось без печати

Так и задумано. Печать и подпись ставятся только на **финальную** версию, а
то, что бот присылает автоматически, — черновик. Плюс проверьте, что
`stamp.png` и `signature.png` действительно лежат в
`skills/kp-builder/assets/` (шаг 10.2).

### Пришло «Дневной бюджет превышен»

Информационное сообщение, бот продолжает работать. Посмотрите `/stats`, чтобы
понять, какой сервис тратит больше всего. Поднять потолок — переменная
`DAILY_API_BUDGET_USD`.

### Пришло «Заявка упёрлась в потолок расходов»

Это другой потолок, жёсткий: `MAX_COST_PER_REQUEST_USD`, по умолчанию $0.50 на
одну заявку. Бот перестал платить за эту заявку и доделал её на том, что успел
собрать, — часть сайтов поставщиков могла остаться непроверенной.

Если такое приходит на каждой заявке, потолок мал: поднимите до `1.0`. Если
приходит редко — значит запрос был слишком общим и бот обошёл много лишних
сайтов; уточните название изделия.

### Бот съел деньги быстрее, чем ожидалось

Чаще всего дело в повторных запросах. Проверьте `/stats`: если много вызовов
`firecrawl`, уменьшите `SCRAPE_CONCURRENCY` или сузьте формулировку запроса —
чем точнее название изделия, тем меньше лишних сайтов обойдёт бот.

Скрипт хранит 14 последних копий и удаляет остальные сам.

### Обновление бота

Railway пересобирает бота автоматически при каждом изменении в ветке
`claude/bot-specification-4anoex`. Ничего нажимать не нужно.

Посмотреть, что происходит: **Deployments** → верхняя запись → **View Logs**.

### Откат на предыдущую версию

Railway → **Deployments** → найдите последнюю рабочую запись → **⋮** →
**Redeploy**. Через минуту вернётся прежняя версия.

### Где смотреть логи

Railway → сервис бота → **Deployments** → верхняя запись → **View Logs**.
По каждой заявке видно, что бот спросил у каждого источника и что получил.
Номер заявки стоит в квадратных скобках в начале строки.

## Шпаргалка

### Команды бота

| Команда | Что делает |
|---|---|
| `/start` | Приветствие |
| `/help` | Список возможностей |
| `/stats` | Расходы на внешние сервисы за сегодня |
| `/session` | Текущая заявка и её статус |
| `/blacklist` | Показать чёрный список |
| `/blacklist add 12 сорвал сроки` | Добавить поставщика №12 с причиной |
| `/blacklist lift 12` | Снять поставщика №12 |
| `/forward` | Переслать приложенный файл на почту |
| `/cancel` | Закрыть текущую заявку |

Заблокированный поставщик не попадает в отчёт вообще — даже с лучшей ценой.

### Что делать в первую очередь, если бот «сломался»

1. Railway → **Deployments** → **View Logs**. Ответ почти всегда там.
2. `/stats` в боте — не кончились ли деньги на сервисах.
3. Не помогло — **⋮** → **Restart** на сервисе бота. Данные не потеряются.

## Что осталось за пределами этой инструкции

Честно про то, чего в системе пока нет:

- **Адреса реестров не проверены на живых данных.** Код написан по описанию
  из ТЗ, но обратиться к сайтам Росздравнадзора из среды сборки не удалось —
  туда нет сетевого доступа. Первый прогон этапа 2 покажет, совпал ли формат;
  правится один файл, см. раздел про «реестр недоступен».
- **Docker-образ не собирался ни разу.** По той же причине: слои базового
  образа не скачиваются из среды сборки. Первую сборку сделает Railway.
- **`users.watch` с Pub/Sub** — почта опрашивается раз в 4 минуты. Когда
  заявок станет много, это стоит заменить на подписку, как и предусмотрено ТЗ.
