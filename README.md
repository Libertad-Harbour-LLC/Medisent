# content-bot

Telegram-бот: отвечает на вопросы, рисует картинки и снимает видео.
Всё через одного провайдера — [api.kie.ai](https://api.kie.ai), один ключ на три модели.

| Что | Команда | Модель |
|---|---|---|
| Ответы и тексты | просто напишите сообщение | `claude-sonnet-5` |
| Картинка | `/img описание` | `gpt-image-2-5-flare-text-to-image` |
| Видео | `/video описание` | `kling-3.0/video` |

Ключи команд: `--ar 16:9`, `--res 2K`, `--bg transparent` для картинки;
`--ar 9:16`, `--sec 8`, `--mode std`, `--sound` для видео.

## Как это устроено

Картинка и видео создаются **асинхронно**: провайдер сразу возвращает `taskId`,
а готовый результат присылает POST-ом на `callBackUrl`. Поэтому боту нужен
публичный HTTPS-адрес — иначе задачи будут создаваться и тратить кредиты,
а результат в чат не придёт.

```
Telegram ──вебхук или polling──> бот ──createTask──> api.kie.ai
                                  ↑                      │
                                  └──POST /callback/kie/<секрет>──┘
                                            (готово)
```

## Два режима запуска

Один и тот же код живёт двумя способами. Режим определяется по окружению,
переключать руками ничего не нужно.

| | Постоянный процесс | Serverless (Vercel) |
|---|---|---|
| Запуск | `python -m bot.main` | `api/index.py`, вызывает Vercel |
| Telegram | long polling | вебхук |
| Память беседы | SQLite на диске | нет, каждый вопрос отдельно |
| Результат в чат | скачиваем и загружаем, до 50 МБ | отдаём Telegram ссылку, до 20 МБ |
| Годится для | локально, Railway, VPS | Vercel |

Почему так: на Vercel нет ни процесса, который живёт между запросами, ни диска,
переживающего вызов функции.

Казалось бы, отсюда следует внешняя база: вы пишете `/video`, функция создаёт
задачу и умирает, а колбэк приходит через минуты уже в другой вызов — где-то
надо помнить, в какой чат вернуть файл. **Но помнить не нужно.** Адрес колбэка
мы задаём сами на каждую задачу, поэтому маршрут доставки едет прямо в нём —
подписанным, чтобы его нельзя было подделать (`services/tokens.py`). Провайдер
возвращает его нам вместе с результатом.

Повторный колбэк ловится без хранилища тоже: сообщение со статусом («Рисую…»)
удаляется ровно один раз, и неудачное удаление означает, что этот колбэк уже
отработал.

## Публикация на Vercel

Внешних сервисов не нужно — ни базы, ни кэша.

**1. Переменные окружения.** Settings → Environment Variables: `TELEGRAM_BOT_TOKEN`,
`KIE_API_KEY` и желательно `TELEGRAM_ALLOWED_USER_IDS` со своим Telegram ID.
Больше ничего: `PUBLIC_URL` подставится из домена проекта, а секреты в адресах
считаются из токена бота.

**2. Деплой.** Любой пуш в ветку продакшена. Пресет — **Python**, Root Directory `./`.

**3. Вебхук Telegram.** Один раз после первого успешного деплоя:

```bash
python scripts/setup_webhook.py --set      # зарегистрировать
python scripts/setup_webhook.py            # посмотреть состояние
python scripts/setup_webhook.py --delete   # снять
```

Или вручную, если Python под рукой нет:

```
https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://<домен>/telegram/<СЕКРЕТ>&secret_token=<СЕКРЕТ>
```

Секрет показывает `python scripts/setup_webhook.py` — он же подставляет его сам
при `--set`.

**4. Проверка.** `https://<домен>/health` должен вернуть
`{"status":"ok","serverless":true,...}`.
Дальше боту: `/start` → ответ сразу, `/img кот` → картинка через минуту,
`/video кот бежит` → настоящая проверка: она проходит через колбэк.

## Запуск постоянным процессом

```bash
cp .env.example .env      # заполнить токен и ключ
docker compose up --build
```

Без Docker:

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
set -a && source .env && set +a
.venv/bin/python -m bot.main
```

Если до этого был зарегистрирован вебхук — снимите его
(`python scripts/setup_webhook.py --delete`), иначе Telegram не отдаст
обновления поллингу.

## Тесты

```bash
.venv/bin/python -m pytest tests/ -q
```

39 тестов, в основном на три места, где ошибка тихая и дорогая: разбор конверта
ошибок провайдера, подпись маршрута в адресе колбэка и путь «колбэк →
сообщение в чат», включая повторный колбэк по одной задаче.

## Что нужно доделать

- **Опрос статуса задачи.** Результат приходит только колбэком. Если
  уведомление потеряется, задача зависнет навсегда. Нужна спецификация
  эндпоинта `get-task-detail` — в документации провайдера на него только
  ссылка, самого описания нет.
- **Оживление картинки в видео.** Kling принимает первый и последний кадр через
  `image_urls` и элементы через `kling_elements`, но для этого файлы надо
  загрузить их File Upload API — его спецификации тоже нет.
- **Учёт расходов.** Провайдер возвращает `creditsConsumed` в колбэке и
  `credits_consumed` в ответе чата. Сейчас это только пишется в лог.

## Грабли провайдера, уже обойдённые в коде

1. **Код ошибки лежит в теле, а не в HTTP-статусе.** HTTP 200 с `code: 402`
   означает «закончились кредиты». Разбор — в `services/kie.py`.
2. **У Kling код продублирован внутри `data`**, а у Claude-эндпоинта конверта
   с `code` нет вообще. Обе ветки обработаны.
3. **`resultJson` — это JSON, упакованный в строку внутри JSON.** Парсится дважды.
4. **Ссылки на результат временные** (`tempfile.aiquickdraw.com`) — ничего не
   хранится, файл уходит в Telegram сразу.
5. **У Claude-эндпоинта `stream` по умолчанию `true`.** Не передать `false`
   явно — получить SSE вместо JSON.
6. **`thinkingFlag` — параметр самого прокси**, в настоящем Claude API его нет.
   Не используется.
7. **Видео в `4K` не помещается в лимиты Telegram.** Бот проверяет размер
   заранее и вместо обрыва предлагает `--mode std`.
8. **Соотношения `27:16`, `16:27`, `9:8`, `8:9` работают только в 1K** —
   разрешение понижается автоматически.
9. **`multi_prompt` помечен обязательным даже для одиночной сцены** — уходит
   пустым списком, иначе 422.
