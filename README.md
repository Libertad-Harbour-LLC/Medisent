# content-bot

Telegram-бот: отвечает на вопросы, рисует картинки и снимает видео.
Всё через одного провайдера — [api.kie.ai](https://api.kie.ai), один ключ на три модели.

| Что | Команда | Модель |
|---|---|---|
| Ответы и тексты | просто напишите сообщение | `claude-sonnet-5` |
| Картинка | `/img описание` | `gpt-image-2-5-flare-text-to-image` |
| Видео | `/video описание` | `kling-3.0/video` |

Ключи команд: `--ar 16:9`, `--res 2K`, `--bg transparent` для картинки;
`--ar 9:16`, `--sec 8`, `--mode std`, `--sound` для видео.

## Как это устроено

Картинка и видео создаются **асинхронно**: провайдер сразу возвращает `taskId`,
а готовый результат присылает POST-ом на `callBackUrl`. Поэтому боту нужен
публичный HTTPS-адрес — иначе задачи будут создаваться и тратить кредиты,
а результат в чат не придёт.

```
Telegram ──long polling──> бот ──createTask──> api.kie.ai
                            ↑                      │
                            └──POST /callback/kie/<секрет>──┘
                                      (готово)
```

Один процесс держит и long polling Telegram, и http-сервер для колбэков.
Соответствие «задача → чат» лежит в SQLite: видео делается минутами, за это
время бот может перезапуститься, и в памяти это хранить нельзя.

## Запуск

```bash
cp .env.example .env      # заполнить TELEGRAM_BOT_TOKEN, KIE_API_KEY, PUBLIC_URL, CALLBACK_SECRET
docker compose up --build
```

Без Docker:

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
set -a && source .env && set +a
.venv/bin/python -m bot.main
```

Тесты:

```bash
.venv/bin/python -m pytest tests/ -q
```

## Переменные окружения

Все — в `.env.example`. Обязательные: `TELEGRAM_BOT_TOKEN`, `KIE_API_KEY`.
Для доставки результата: `PUBLIC_URL` (адрес сервиса снаружи) и
`CALLBACK_SECRET` (случайная строка, становится частью секретного пути колбэка).
`TELEGRAM_ALLOWED_USER_IDS` пустой означает, что бот отвечает кому угодно.

## Деплой на Railway

Платформа сама собирает образ по `Dockerfile`, выдаёт `PORT` и публичный домен.
Домен нужно скопировать в `PUBLIC_URL` — на него провайдер будет слать колбэки.
Данные SQLite положите на volume, примонтированный в `/app/data`, иначе при
редеплое потеряются задачи, которые ещё в работе.

## Что нужно доделать

- **Опрос статуса задачи.** Сейчас результат приходит только колбэком. Если
  уведомление потеряется, задача зависнет навсегда. Нужна спецификация
  эндпоинта `get-task-detail` — в документации провайдера на него только
  ссылка, самого описания нет.
- **Оживление картинки в видео.** Kling принимает первый и последний кадр через
  `image_urls` и элементы через `kling_elements`, но для этого файлы надо
  загрузить их File Upload API — его спецификации тоже нет.
- **Учёт расходов.** Провайдер возвращает `creditsConsumed` в колбэке и
  `credits_consumed` в ответе чата. Сейчас это только пишется в лог, таблицы
  расходов нет.

## Грабли провайдера, уже обойдённые в коде

Собрано из спецификаций, пригодится при доработке:

1. **Код ошибки лежит в теле, а не в HTTP-статусе.** HTTP 200 с `code: 402`
   означает «закончились кредиты». Разбор — в `services/kie.py`.
2. **У Kling код продублирован внутри `data`**, а у Claude-эндпоинта конверта
   с `code` нет вообще. Обе ветки обработаны.
3. **`resultJson` — это JSON, упакованный в строку внутри JSON.** Парсится дважды.
4. **Ссылки на результат временные** (`tempfile.aiquickdraw.com`). Файл
   скачивается и уходит в Telegram сразу, URL нигде не хранится.
5. **У Claude-эндпоинта `stream` по умолчанию `true`.** Не передать `false`
   явно — получить SSE вместо JSON.
6. **`thinkingFlag` — параметр самого прокси**, в настоящем Claude API его нет.
   Не используется.
7. **Видео в режиме `4K` не помещается в лимит Telegram** (50 МБ на файл от
   бота). Бот проверяет размер и вместо обрыва предлагает `--mode std`.
8. **Соотношения `27:16`, `16:27`, `9:8`, `8:9` работают только в 1K** —
   разрешение понижается автоматически.
9. **`multi_prompt` помечен обязательным даже для одиночной сцены** — уходит
   пустым списком, иначе 422.
